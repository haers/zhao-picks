# Zhao Picks · 我的开源精选

记录我亲自用过、觉得不错、愿意推荐的开源项目。

另保留有明确证据的[项目评测](#项目评测)，包括实际试用和源码选型评估。逐篇说明验证范围与未验证部分；评测收录不等于推荐，也不要求 Star、Fork 或保留本地源码。

从真实使用出发，写清项目解决什么问题、为什么值得推荐，以及使用中遇到的不足。推荐代表个人体验，适合自己的工具也未必适合所有人。

## 收录原则

- **区分推荐与评估**：正式推荐至少实际试用过；源码选型评估须列明阅读版本、判断依据和未验证范围，不写成亲测推荐。
- **有明确用途**：能解决具体问题，写清适合什么场景。
- **分别判断取舍**：是否当前采用、是否保留源码、是否值得分享分别说明；不采用或不保留源码，也可以形成有依据的选型评估。重复版本优先合并比较，不按清理数量凑文章。
- **说明推荐理由**：记录自己的判断，不按 Star 数量排名。
- **如实记录不足**：区分官方提供的功能与自己实际验证的体验，不把初次试用写成长期使用。
- **保留来源**：优先链接原项目，个人 Fork 作为整理入口另行标注。
- **内容提示**：收录涉及宗教的资料项目时，在索引中标注“宗教资料”，并在介绍正文开头明确提示，例如“以下内容涉及宗教（佛教）文献与相关论述，请按个人兴趣选择阅读。”介绍聚焦资料用途与来源，不将收录表述为信仰立场或劝导。
- **持续更新**：记录体验日期和使用状态；停用后保留原因，方便以后回看。

## 健康与休息

### Stretchly

让长时间使用电脑的人记得停下来休息。

| 项目 | 说明 |
| --- | --- |
| 原项目 | [hovancik/stretchly](https://github.com/hovancik/stretchly) |

| 官方下载 | [上游 Releases](https://github.com/hovancik/stretchly/releases) |
| 支持平台 | macOS、Windows、Linux；具体系统版本要求见上游文档 |
| 上游许可证 | BSD-2-Clause，以原项目许可证为准 |
| 使用状态 | 已试用，初步推荐 |
| 最近体验记录 | 2026-10-21 |

**为什么收录**

我实际用了一下，觉得不错，因此把它作为这份清单的第一个项目。它解决的是长时间使用电脑时容易忘记休息的问题，适合需要此类提醒的人尝试。

**功能参考**

上游文档介绍了短休息和长休息提醒、提醒前通知，以及可调整的休息偏好。这些是官方功能说明，不代表我已经逐项验证。

**体验与不足**

目前是初步试用记录，尚未形成长期使用结论。提醒对工作节奏的影响、常用配置和具体不足，将在后续使用后补充。

**Fork 说明**

`zhao-stretchly` 是我为方便个人整理而保留并重命名的 Fork，目前没有自行修改上游代码的计划。项目由原作者和社区开发维护；使用说明、版本更新和下载优先参考原项目。

## 开发与界面

### shadcn-admin

用于查看后台壳、表格、筛选和表单如何组合的 React 界面示例集。推荐给需要选择后台 UI 基础、比较原版交互或学习组件组织的人。

| 项目 | 说明 |
| --- | --- |
| 原项目 | [satnaing/shadcn-admin](https://github.com/satnaing/shadcn-admin) |
| 我的 Fork | [haers/zhao-shadcn-admin](https://github.com/haers/zhao-shadcn-admin) |
| 在线体验 | [官方 Demo](https://shadcn-admin.netlify.app/) |
| 上游许可证 | MIT，保留原作者 Sat Naing 署名 |
| 体验版本 | `e16c87f213a5ba5e45964e9b67c792105ec74d26`；包版本 2.2.1 与同名标签的提交不同 |
| 使用状态 | 已作本机试用；后台壳与表格能力已有实际采用 |
| 最近体验记录 | 2026-10-23 |

**为什么收录**

它已帮助个人项目建立后台界面，独立原版还可用于查阅完整示例、对照适配与分享。个人 Fork 用于保留这个独立入口，暂不做业务开发，也不自动追随上游更新。

**实际体验与不足**

本机使用 Node 26.3.0、pnpm 10.11.0 完成构建，并检查仪表盘、任务搜索空态、用户弹窗和手机侧栏。390 px 手机视口没有整页横向溢出，但表格右侧列仍需横向查看，搜索提示有截短。

它是前端 UI 样板，上游明确说明并非完整 starter template。Add User 仅展示提交信息，不保存真实用户；登录、权限、持久化和业务 API 需要另行实现与验证。此次体验不代表全部路由或长期稳定性验收。

## 如何维护这份清单

新项目先加入索引，再按下面的格式补充记录。分类随实际收录内容增加。

```text
项目名称：
一句话用途：
原项目地址：
我的 Fork 地址（可选）：
为什么推荐：
实际使用场景与体验：
已遇到的不足或尚未验证的部分：
使用状态：已试用 / 持续使用 / 已停用
体验日期：YYYY-MM-DD
```

欢迎通过 Issue 推荐项目；经我实际使用并认可后，再加入正式清单。
